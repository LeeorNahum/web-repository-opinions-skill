# Agent Plugins

Package each shared skill and any shared protocol implementation once across agent hosts. Add small host-specific descriptors only where each host's installation contract requires them, and keep host-specific setup in its owning adapter. Generate each host descriptor's name, version, and endpoint from one source file, and in CI validate the built package output, not the source, with each host's own validator where one exists.

Lay the plugin out by the Agent Plugins standard, with `plugin.json` at its root as that source file, each skill at `skills/<skill-name>/`, and its protocol connections in `mcp.json`. Generate the descriptors a host still reads from a path of its own, such as Claude Code's `.claude-plugin/plugin.json` or Gemini CLI's `gemini-extension.json`, beside them. Commit every skill in the plugin as regular files in the plugin's own tree, so a host that installs from a clone, a host that installs a release archive, and a directory that reviews the files all receive the same plugin from one tree. Release a platform-independent plugin as one generic archive with the descriptors at its root.

When a product ships an agent plugin, it ships one, in one repository of its own, and the skills that work only with it live inside it rather than in repositories of their own. A directory sets the visibility it needs, so check it before choosing the repository's visibility: Anthropic's plugin directory requires the repository to be public before the listing goes live, while OpenAI's takes an uploaded archive and needs no public repository.

Treat discovery and freshness as separate contracts. Marketplace metadata, installed package files, a live tool catalog, and instructions already read into a conversation can each update at a different time. An update reaching one layer does not prove that another layer refreshed.

Verify automatic discovery, instruction following, and update pickup in fresh sessions. Test discovery and instruction following apart from explicit invocation, which proves only that a skill can run, and treat a description found in a catalog as proof of discoverability, not that the model read or followed the instructions. Test main sessions and child agents separately because tool and instruction inheritance is host behavior, not a property of the package format. State compatibility from observed client behavior rather than from a shared file format alone.

Before grading a fresh-client run, confirm that the intended configuration, plugin version, skill catalog, and connection reached that session. An installed package or a configuration listing proves setup state, not model-visible context. Classify setup failures separately from product behavior failures.
